# ZAVAEBATEL UC — безопасная версия

## Текущий режим
- Каталог получает данные от Nexus; если поставщик или конфигурация недоступны, сайт показывает ошибку, а не фиктивные товары.
- Реальные заказы, платёжные инструкции, загрузка чеков и выдача UC выключены в интерфейсе и API. Это намеренное ограничение до проверки платежного процесса.
- Сервер не отправляет заказы поставщику Nexus и не выдаёт UC автоматически.
- Nexus API endpoint и формат ответа унаследованы из кода проекта. Владелец должен подтвердить их по актуальной документации/доступу поставщика: подключение к реальному Nexus из этой среды не выполнялось.

## Render: пошаговая настройка
1. Создайте/выберите PostgreSQL в Render. В Web Service → Environment добавьте `DATABASE_URL` со значением Internal Database URL. Не вставляйте его в Git.
2. Добавьте `NEXUS_API_BASE=https://nexus.amadeustech.dev`, `NEXUS_SHOP_ID`, `NEXUS_SHOP_TOKEN` (секреты только в Render).
3. Установите `NEXUS_PRICE_CURRENCY=USD`. Валюта должна соответствовать документированному ответу поставщика; неподдерживаемое или отсутствующее значение блокирует каталог.
4. Установите `NEXUS_USD_RUB=85` и `SALE_MARKUP=0.20`. Цена: USD × курс × (1 + наценка), округление до 2 знаков. Курс 85 — пример/выбранная настройка, не актуальная рыночная котировка.
5. Для административной панели задайте длинный уникальный `ADMIN_PASSWORD` и случайный `SESSION_SECRET` длиной не менее 32 символов. Без PostgreSQL и этих параметров вход отключён; production-сессии хранятся в PostgreSQL.
6. Оставьте `SBP_ENABLED=false`. В этой версии создание заказов и платежные инструкции намеренно не включаются автоматически даже при true; перед открытием продаж нужна отдельная проверка и реализация полного потока.
7. Выполните Deploy вручную после ревью PR. Эта ветка сама по себе не меняет production-деплой.

## Проверка
- `GET /api/health` — состояние сервера и конфигурации БД.
- `GET /api/catalog` — живой каталог либо понятная JSON-ошибка. Не публикуйте содержимое заголовков или ответы поставщика.
- `GET /` — витрина; `GET /admin` — вход в админку.
- Запустите `npm ci`, затем `npm test` и `npm start` локально с тестовыми/безопасными переменными. Не делайте реальных заказов для проверки.

## Откат
В Render откройте Deploys и выполните rollback к предыдущему успешному deploy. Не переписывайте Git-историю; при необходимости откатите merge отдельным revert-коммитом/PR. Перед миграцией production-базы сделайте резервную копию.

## Ограничения и ручные действия владельца
- Проверьте документацию Nexus, схему каталога, валюту, реальные product ID и права токена.
- Проверьте PostgreSQL, сессию администратора и защиту чеков в тестовом окружении.
- Подготовьте законные реквизиты/условия оплаты отдельно; не включайте платежи до проверки банковского процесса, персональных данных и возвратов.
- Не подтверждайте оплату по скриншоту: сверяйте поступление в банковском приложении. Выдача UC остаётся ручной и не реализована.
