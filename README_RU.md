# ZAVAEBATEL UC — безопасная версия

## Текущий режим и ограничения

- Витрина загружает каталог с сервера; при ошибке поставщика или конфигурации отображается ошибка, а не фиктивные товары.
- Реальные заказы, приём платежей, платёжные инструкции, загрузка чеков и автоматическая выдача UC выключены. **POST /api/orders** и **POST /api/orders/:id/receipt** возвращают HTTP 503 независимо от **SBP_ENABLED**.
- Сервер не создаёт заказы у Nexus и не выдаёт UC автоматически. Не включайте продажи, платежи или выдачу UC через изменение переменных окружения.
- Статические файлы обслуживаются только из **public/**; корневые файлы проекта, включая .env, package.json и server.js, не публикуются.
- CSP использует **script-src 'self'**; Helmet устанавливает security headers. В публичных JS/HTML не должно быть секретов.
- Административные данные требуют PostgreSQL, **ADMIN_PASSWORD** и **SESSION_SECRET** (не менее 32 символов). Изменяющие административные действия требуют CSRF-токена; в production cookie сессии имеет **Secure**.
- Доверие к forwarded IP по умолчанию выключено. Указывайте **TRUST_PROXY_HOPS=1** только если приложение действительно находится за одним доверенным reverse proxy.
- Автоматическая инициализация схемы БД по умолчанию выключена. **DB_AUTO_INIT=true** — явный opt-in для создания отсутствующих таблиц/добавления колонки; инициализатор не переписывает статусы существующих заказов. Проверяйте его только на отдельной тестовой БД.
- Для удалённой PostgreSQL проверка TLS-сертификата включена. Для локального хоста TLS не используется.
- Nexus endpoint, заголовок авторизации, category ID, envelope ответа и поле цены унаследованы от старого кода. Подключение к реальному Nexus не выполнялось; контракт необходимо сверить с документацией поставщика.

## Установка и проверки

Требуются Node.js 20+ и совместимый npm. Workflow использует Node.js 20, npm cache и **npm ci**; для воспроизводимой установки необходим настоящий **package-lock.json**.

В окружении с доступом к npm registry, в рабочей ветке:

1. Если lock-файла ещё нет, выполните **npm install --package-lock-only** и закоммитьте созданный npm lock-файл. Не редактируйте его вручную.
2. Выполните **npm ci**.
3. Выполните **npm test**.
4. Выполните **npm audit --omit=dev**.

Все команды должны завершиться успешно до слияния PR. Если npm registry недоступен, зафиксируйте сетевую ошибку и повторите команды в подключённом окружении; не заменяйте **npm ci** на **npm install** в CI и не заявляйте аудит успешным без результата команды.

## Переменные окружения

Задавайте переменные только в локальном тестовом окружении или в хранилище секретов платформы; реальные значения не коммитьте и не включайте в отчёты:

- **PORT**, **NODE_ENV**.
- **NEXUS_API_BASE**, **NEXUS_SHOP_ID**, **NEXUS_SHOP_TOKEN**.
- **NEXUS_PRICE_CURRENCY**, **NEXUS_USD_RUB**, **SALE_MARKUP**.
- **DATABASE_URL**, **PGSSL_CA** (необязательный CA-сертификат для PostgreSQL), **DB_AUTO_INIT**, **TRUST_PROXY_HOPS**.
- **ADMIN_PASSWORD**, **SESSION_SECRET**.
- **SBP_ENABLED** и **SBP_PAYEE_NAME**, **SBP_BANK_NAME**, **SBP_PHONE**, **SBP_PAYMENT_INSTRUCTIONS** остаются выключенными/пустыми; их наличие не активирует не реализованный безопасный платёжный процесс.

Для безопасного тестового запуска не задавайте **DATABASE_URL**, **DB_AUTO_INIT**, **ADMIN_PASSWORD** или **SESSION_SECRET**. Сервер должен отвечать на административные запросы отказом, а создание заказов и загрузка чеков останутся отключёнными.

## Маршруты и проверка

- `GET /` — витрина.
- `GET /logo.svg`, `GET /storefront.js`, `GET /admin.js` — статические файлы из `public/`.
- `GET /admin` — страница входа администратора.
- `GET /api/health` — состояние сервера/БД.
- `GET /api/catalog` — каталог либо понятная JSON-ошибка.
- `GET /api/admin/orders` и загрузка чеков доступны только при корректной конфигурации БД и авторизованной админ-сессии.
- `POST /api/orders` и `POST /api/orders/:id/receipt` намеренно отключены.

## База данных и миграции

Не подключайте этот PR к production PostgreSQL для тестирования. Перед любыми миграциями используйте отдельную тестовую базу и резервную копию. Не запускайте миграции, которые изменяют существующие статусы или ограничения, без отдельного плана миграции и проверки совместимости старых данных.

## Что блокирует безопасный запуск продаж

1. Несмотря на успешные CI и аудит production-зависимостей, перед продажами всё ещё необходима отдельная проверка полного заказа/платежа/возврата и ручного контроля выдачи UC; эти функции остаются отключёнными.
2. Не проверены на реальном поставщике Nexus URL, авторизация, схема каталога, валюта и идентификаторы продуктов.
3. Не проведён тест интеграции с Render и PostgreSQL.
4. Полный процесс заказа, подтверждения оплаты, обработки чеков, возвратов и выдачи UC не реализован и должен оставаться выключенным.
5. Перед открытием продаж нужны отдельные проверки защиты персональных данных, банковских операций, аудита админ-действий и восстановления после ошибок.

## Откат

Не изменяйте production в рамках этого PR. После будущего отдельно согласованного деплоя используйте штатный rollback Render к предыдущему успешному deploy. Не переписывайте историю Git; исправления выпускайте отдельными коммитами/PR.
